# Showdown bosses, victory, and Endless — native contract

Research date: 2026-10-14. Authoritative source: uploaded APK assets in `../reference-apk/assets`; references below are native source line numbers. This is source-derived research, not a claim of full APK/device execution. No product changes accompany this document.

## Content and eligibility

`game.lua:280,291-292,297-298` defines all five showdown bosses. Each pays **$8**; Bell, Leaf, Acorn, Heart use base multiplier **2**, Vessel **6**. At default Ante 8 base **50,000**, targets are **100,000**, Vessel **300,000**. `blind.lua:107` additionally applies starting `ante_scaling`.

The `boss.min/max = 10` metadata does **not** determine showdown eligibility. `functions/common_events.lua:2404-2408` chooses showdown bosses when `ante >= 2` and `ante % win_ante == 0`; other antes use regular bosses meeting minimum ante. Default `win_ante = 8` is `game.lua:2076`. Least-used selection and bans still apply. Thus showdown returns at 16, 24, etc.; a custom win ante must also change selection and save validation, not only the win screen. FTP/demo alternate eligibility is a separate source branch, not the approved full-version default.

## RNG and order

`functions/misc_functions.lua:256-270` sorts `pseudorandom_element` candidates by persistent card `sort_id` when present, then reseeds and performs one inclusive integer draw. Both Bell and Heart therefore use creation order, not current hand/joker display order. Native `card.lua:24-25` assigns monotonically increasing creation IDs; the existing plain52 `canonicalCards` and joker `creationOrdinal` are viable corresponding identities within their verified scope.

| Point | Native calls / streams |
| --- | --- |
| Amber setup, more than one joker | Three `pseudoseed('aajk')` advancements. Each seeds the native math generator, sorts candidates by `sort_id`, then draws `n-1` Fisher–Yates integers (`cardarea.lua:578-580`, `misc_functions.lua:209-219`). Crucially, shuffle two and three each **re-sort**; they are not permutations of the immediately previous displayed order. |
| Bell initial draw and each play/discard redraw lacking a forced card | One `pseudoseed('cerulean_bell')`, one candidate integer draw, including a one-card pool. No consumption if an existing forced held card remains marked. |
| Heart initial draw and armed post-play draw | One `pseudoseed('crimson_heart')`, one candidate integer draw, including a one-joker pool. No poll on ordinary discard or zero jokers. |
| Leaf / Vessel | No random call for their inherent effect, sale disable, or target multiplier. |

Use `nextApkSeed` plus `createApkMathState`/`nextApkMathRandom` for shuffle; `nextApkRandom(..., 1, candidateCount)` for choice. Preserve the resulting `mathState`, not just named stream counters. Existing `shuffleApkDeck` is restricted to canonical playing cards and cannot directly shuffle arbitrary joker objects.

Relative order is a native event-queue issue: Acorn enqueues setup shuffles; deck shuffle is initiated in `new_round`, and draw hook runs after draw events. Before claiming integrated RNG parity, extract/execute those ordered callbacks and verify `aajk` against `nr<ante>` and any setup-joker RNG. Named keyed draws normally isolate choices, but last global math state affects later unkeyed effects. An approximate event ordering is insufficient proof.

## Victory and Endless lifecycle

`functions/state_events.lua:87-110`: calculate round success and end-of-round joker save/rental/perishable effects first. At the win ante Boss, native sets `game_won`/`GAME.won` (`112-122`); the success branch alone performs victory notification (`141-191`). The literal native code also sets `won` on a losing win-ante Boss before the game-over branch: this is an apparent source quirk; do not silently treat it as proven intended UX or change it without recording the divergence.

On a successful win Boss, `win_notified` becomes true once and queues `win_game` when state reaches `ROUND_EVAL` (`174-191`). Boss end-round cleanup increments ante (`258-269`) and refreshes voucher before round evaluation (`279-300`). `game.lua:3647-3661` saves round evaluation. Victory uses an unescapable paused overlay (`state_events.lua:26-39`), **before collecting cashout / entering the next shop**. Profile wins/unlocks/stakes are applied at this one-time transition (`1-24,71-75`), with seeded/challenge gates preserved.

The win overlay offers new run, main menu, and Endless (`UI_definitions.lua:2891-2897`). Endless invokes ordinary overlay exit: unpauses and closes overlay (`button_callbacks.lua:1395-1407`). It **does not** create a new run, reroll a boss, refill hands, grant money, or advance ante a second time. The queued continuation sets round text to Endless (`state_events.lua:76-84`). Existing round evaluation then proceeds to the normal cashout and next-ante shop. Later losses retain victory status and must not reset win streak (`state_events.lua:135`). No repeat victory popup at Ante 16, due to `win_notified`.

Minimal existing-stack representation: keep the completed round identity for payout and existing next-ante shop generation, add durable `winAnte`, `won`, `winNotified`, and a win-overlay acknowledgement/pending flag. A dedicated `CONTINUE_ENDLESS` action clears pending once, with revision guarding. While pending, cashout and inventory/gameplay actions must be locked. An extra core phase is optional; preserving `round_won` plus explicit pending status avoids extensive phase duplication. This is an implementation proposal, not a native field-name requirement. Ensure native next-ante RNG occurs once at the currently established lifecycle boundary; an overlay close must consume no gameplay RNG.

## Save/resume contract and affected modules

Native saves serialize full `GAME`, `STATE`, card areas and blind (`misc_functions.lua:1472-1507`). Blind save/load retains `disabled`, target, and triggered state (`blind.lua:684-728`); Card save includes `sort_id`, facing and debuff (`card.lua:4713-4730`), and ability includes forced selection. `prepped` is not in `Blind:save`; stable input states have already finished `drawn_to_hand`. ## Priority and correctness blockers

1. **Feasible now:** native isolated oracles for final-five hooks, choice order and Acorn shuffle; implement final-five state/save/scoring/selection through Ante 8. Add exact positive, no-trigger, and boundary cases, including 0/1/2 jokers and discard not rerolling Heart.
2. **Next:** durable victory pending/acknowledgement at round evaluation, idempotent cashout and new-run/main-menu paths; browser checks for forced selection and hidden-joker sale/reorder. Profile progression is a separate existing missing subsystem; a victory popup alone does not satisfy native unlock/stake/career behavior.
3. **Endless prerequisite:** reproduce `get_blind_amount` native Number formula for ante>8 (`misc_functions.lua:922-953`) and compare pinned LuaJIT fixtures. It uses double exponentiation, floor, logarithmic two-significant-digit truncation and modulo, not a geometric BigInt table. Very high ante can overflow Lua number; current BigInt state/save representation cannot directly represent native infinity/NaN. Establish tested supported range and recorded overflow behavior before claiming full Endless parity; do not introduce an arbitrary cap as an unmarked final rule.
4. **Integrated parity blocker:** observe/extract callback ordering involving Acorn, deck shuffle and random first-hand/end-round joker hooks; isolated hook tests cannot certify the full Android event queue. Current stack also lacks complete end-of-round joker/rental/perishable/profile coverage, which affects victory order and rewards.

## Executed overflow/save boundary — 2026-10-14

Rebuilt pinned upstream LuaJIT `43d0a19158ceabaa51b0462c1ebc97612b420a2e` outside the game repository after the previous transient runtime disappeared. Verified the source files against upstream Git blob hashes; executable reports `2.1.1700008891`. Regenerating `showdown-fixtures.json` produced a byte-identical file, with JIT/interpreter equal. This recovery does not constitute Android execution.

Executed the original `get_blind_amount`, `number_format`, `STR_PACK` and `STR_UNPACK` with default scaling and explicit `G` adapter. Ante39 returns NaN, displays `nan`, and all tested success comparisons (`0>=target`, `1e300>=target`, `0-target>=0`) are false. Native packing emits a bare `nan` expression for the target; unpacking with no global `nan` drops the `chips` field to nil, and subsequent target arithmetic errors. Thus copying the native packer would reproduce save corruption, not a valid high-Ante representation. Task6 must preserve the unreachable NaN gameplay target explicitly in durable JSON, record this deliberate save-behavior divergence, and keep native comparisons/display without an invented final Ante cap.

## Current interfaces and integration risks

- `src/core/score.js:9` is pure `scoreHand`; `105` discovers scored repeats, `134–139` handles held cards once; independent/main pass follows. `src/content/jokers.js` has identity-only stateless helpers, not mutable target ability/context dispatch. Native growing/lifetime/copy content cannot be admitted solely through those helpers.
- `src/core/run.js:93` owns revision-checked actions. Delegates inventory, consumable, pack, skip and shop actions before its play branch. START_BLIND (`138`) currently creates boss state, shuffles then draws; hooks need an explicit point before normal draw and another after first draw. PLAY_HAND (`190`) calls pure scorer before cloning/committing; mutable before/after must become part of a returned transaction with prestate captured for replay. DISCARD currently mostly moves cards and decrements count (`265`); it is not yet a per-card lifecycle mechanism.
- `src/core/cashout.js:50` settles success and captures a quote; `run.js:109` CASH_OUT pays it and clears hand. Endround effects must resolve once at earned-win settlement before quote freezing, not on repeated CASH_OUT or UI reload. Loss interception must run before terminal game_over. Decide the transaction boundary explicitly and test interrupted animation reload.
- `src/core/shop.js:57`, `inventory.js:10`, `skip-blind.js:44`, `consumables.js:124`, and pack reducer each commit their own cloned transaction. Generic hooks must integrate successful paths, never rejection or a capability query. Creation buffers must reserve capacity before asynchronous-source-equivalent effects, preserve order, and release exactly once.
- `src/core/save.js` strictly recomputes score trace/provenance from historical inputs. Persist actual pre-score mutable Joker state, creation/deletion snapshots, counter changes, held/endround data and action RNG chronology before widening validators. Current state may have removed Seltzer or mutated another Joker, so current inventory alone cannot replay the last score.
- RNG: Stone face calls and repeated stateful predicates consume raw math draws. Copying can invoke an accessor multiple times. A new pure boolean utility must not accidentally cache away native calls; use original-source oracle chronological draw logs. Preserve previous legacy save semantics explicitly.
- UI animation uses committed state first. Removed lifetime Joker and removed playing card need animation snapshots/anchors surviving commit. Marker source identity cannot be inferred from inventory after removal. Held repeat phase must not silently animate scoring-centre anchors.

## Executable decomposition without approximations

1. Prove held repetition and shared face accessor against original scoring/endround functions: Mime + Steel/Queen/Gold; Pareidolia + existing face Jokers + Stone + boss cases. Integrate strict historical replay and markers before admitting them to offers.
2. Add context-target resolution with bounded copying and two identities; golden fixtures covering chain, cycles, main, scored, held, debuff, incompatible passive and mutation exclusion. Admit Blueprint/Brainstorm only when every admitted target family is routed through resolver, including recognition and cashout boundaries as native allows.
3. Add per-instance mutable ability state and atomic before/after transaction. Seltzer proves score→after→remove; use native `j_selzer`, tenth-play test, copied decrement excluded. DNA proves actual physical creation/copy with item 4 identity rules; transformations must preserve identity and differing enhancement/edition/seal dimensions.
4. Add reducer lifecycle envelope for successful startblind/discard/round end/skip/shop/use/creation/removal. Prove with the real sentinels in inventory above and pinned original-source oracles. Implement only exact native effects; unsupported content stays rejected. A no-op hook API alone does not close the claimed family.
5. Cross-context regression: mutation + copy + retrigger, create capacity reservations, remove while iterating, boss debuff and Hook discard, negative expansion, save/load before/after win, generated next action vs uninterrupted run, replay rejects stripped historical state. Core/UI/device limitations reported separately.

## Selected item 6 sentinel slice (lead coordination)

The concrete implementation slice admits seven Joker keys: `j_mime`, `j_pareidolia`, `j_blueprint`, `j_brainstorm`, `j_selzer`, `j_dna`, `j_marble`. This raises the supported catalogue from57 to64 when their reducers, save validators, descriptions and acquisition paths all pass. Remaining86 effects belong item7. Root owns scoring/run/save and acquisition integration; this research worker owns the pure content predicates and resolver.

- `jokerEffectContext(jokers,index)` returns `null` or `{source,target,copied}` using references to actual owned instances. No inventory mutation or copied metadata. `source.id` animates, `target.id` identifies ability holder. Call freshly for each native context; do not cache through deletion/reorder.
- `isCardFace(card,jokers,{debuffed,rankGetter})` defaults debuff to card flag, calls supplied native-order rank accessor once only after debuff test, tests direct active Pareidolia presence; copy cards do not add another Pareidolia. Explicit debuff override permits boss-specific calling semantics.
- `repeatHandsRemaining` is optional on normal `j_selzer` offer/initial owned card, semantically10; explicit persisted values must be safe integers1..10. Other keys cannot carry it. Internal final after transaction may calculate0 but must remove that owned instance before commit. Strict score history must capture preplay inventory/lifetime so last-score replay still works after removal.
- DNA before context: only first played hand of round with exactly one physical played card creates a physical copy; copying through Blueprint can create an additional copy, so per-target `not blueprint` is not inferred globally. Native `card.lua:3505–3526` must be the mutation/copy oracle.
- Marble settingblind context creates one Stone playing card per actual activation before ordinary draw, with physical identity rules from item4 and subsequent added-card notification. Raw RNG/card pool selection must be oracle-backed; create/copy utility must not silently reshuffle deck.
- Purple discard seal, Gold scoring seal, Blue held endround seal and Red scored/held repetition seal prove discard/endround/repetition creation contracts. Four seal Spectral acquisitions and Aura prove modifier acquisition in this slice; full Spectral/pack catalogue remains item8. Mechanism completion is bounded to these concrete consumers; unsupported lifecycle consumer content stays rejected until item7.

The exhaustive context table above remains the forward contract needed by item7. Minimal admission alone does not prove every unimplemented consumer or global passive. Explicit reporting should distinguish tested concrete hooks from planned dispatcher extension points.

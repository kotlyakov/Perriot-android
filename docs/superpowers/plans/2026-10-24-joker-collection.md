# Восстановление и коллекция 150 джокеров — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. User explicitly requires autonomous execution; no repeated design approval.

**Goal:** Восстановить и сохранить утверждённый UI, затем заменить 150 повторяющихся карт индивидуальными иллюстрациями и утверждёнными именами, показать только коллекцию.

**Architecture:** Сохранить существующие JS ESM/WebView и SVG. Каталог механик и canonical ID не изменять. Общий каталог художественных паспортов связывает имя, сюжет и иллюстрацию; общий artwork используется коллекцией, магазином, наборами и принадлежащими картами.

**Tech Stack:** JS, SVG, CSS, Node test, Playwright, Kotlin WebView.

**Spec:** docs/approved-ui/Pierrot_APPROVED_UI.md; docs/art/joker-production.md (утверждённые 150 строк, подготовить из сохранённой переписки).

## Global Constraints

- Единый стиль B «Печатная мастерская»: кремовая бумага #f0e5c8, зелёная краска #143d39, киноварь #ca3d2a, синие фишки; Rubik.
- У каждого из 150 джокеров утверждённые имя/сюжет; ID, правила, RNG, экономика и сохранения прежние.
- Одну карту нарисовать и проверить перед следующей; у каждой собственная композиция, общие только графические примитивы и материал печати.
- Название полностью в пределах карты; перенос слов разрешён, многоточие/обрезка нет.
- Пользователь 24.10 прямо разрешил push. Сначала отдельно сохранить восстановление, затем художественный этап. APK не требуется.

## Review Focus

- Длинные названия при размерах1536×688,915×412,568×320 и в компактном просмотре390px.
- Копии legacy ID должны иметь тот же рисунок/имя; счётчики текущих эффектов остаются.
- Карты в неизвестном/закрытом состоянии не раскрывают описание/изображение; показ коллекции явно демонстрационный.
- Издания/наклейки/ослабление не перекрывают название и не заменяют сюжет.
- Самостоятельный HTML должен работать без сети и включать актуальную графику, а не старый дублированный renderer.

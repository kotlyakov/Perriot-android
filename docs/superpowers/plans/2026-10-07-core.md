# Первая основа ядра — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Создать проверяемые RNG и точную арифметику для нового ядра без зависимости от UI и неподтверждённых эффектов.
**Architecture:** Чистые ES modules, значения возвращаются без изменения аргументов; никаких внешних зависимостей. Состояние RNG — JSON, рациональные числа — нормализованные пары BigInt.
**Tech Stack:** JavaScript, Node node:test.
**Spec:** `../../design.md`, `../../../ROADMAP.md`, этап 2. Подплан охватывает только две независимые основы; он не заменяет остальные задачи этапа.

## Global Constraints

- Новый код; не копировать старый прототип.
- RNG не используется анимациями; совпадение seed с оригиналом не обещается.
- Состояние JSON: `{algorithm:'counter32-v1', state:uint32}`. Алгоритм собственный, фиксирован для повторов этой игры. Шаг счётчика +0x9e3779b9 и обратимое смешивание xor-shift/умножение на нечётные uint32 константы покрывают полный диапазон выходов.
- Создание состояния из непустой seed-строки: FNV-1a по UTF-16 code units; все uint32 состояния допустимы. Это контракт нового проекта, не утверждение о Balatro.
- `randomInt(rng,maxExclusive)` возвращает `{value,rng}`; rejection sampling устраняет смещение остатка. Допустимый предел 1..2^32 включительно.
- Fraction: `{n:bigint,d:bigint}`; знаменатель положительный, gcd сокращён, ноль имеет знаменатель 1. Отрицательный floor округляет вниз.

## Review Focus

- Повреждённое состояние RNG: отклонить дроби, неправильный алгоритм; RNG тест в задаче 1.
- Некорректный предел: отказ без изменения аргумента; задача 1.
- Взаимное влияние потоков: два независимых состояния не меняют друг друга; задача 1.
- Значения больше safe integer и дробные множители: точность BigInt; задача 2.
- Нулевой знаменатель и отрицательные дроби: ошибка/математический floor; задача 2.

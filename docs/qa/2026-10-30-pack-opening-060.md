# Открытие Таро — 0.4.60 / У-79

База: fcecd4961498c3d49af735958a2af561accad302, ветка fix/enhancement-visuals. Замечание относится к открытию набора, отдельно от получения карты У-55г.

## Воспроизведение и причина

Реальный сгенерированный Mega Arcana, 203 действия истории, Chromium 138, viewport915×412, CPU×4, загруженные шрифты. При открытии три полных построения интерфейса удаляют 16 карт руки и 10 карт набора; раскрытые карты отсоединяются от DOM при снятии busy. Раскрытие коробки/карт, раздача руки и деньги идут последовательно; целевая рука сначала появляется, затем создаётся и раздаётся заново. Все восемь полётов меняют left/top на каждом кадре.

Регрессия сохранения узлов сначала RED (revealedPreserved=false, removed16/10), после исправления GREEN (0/0). Отдельный RED layoutFlights8, затем GREEN0. Проверки не используют хрупкий порог общего wall-time.

## Исправление

- Первое построение создаёт руку один раз; при снятии busy обновляются выбор/disabled существующих карт.
- При том же неизменённом packState сохраняются узлы набора, обновляются mutable bindings состояния/callbacks/busy. Новое состояние набора строит новые варианты.
- Раскрытие, раздача и деньги выполняются одновременно после успешного сохранения. Ошибка сохранения не показывает успешное открытие.
- Раздача использует transform translate с прежними начальной/средней/конечной координатами, поворотом, длительностью и задержками; left/top остаются в конечном положении. Изменение общего helper также ускоряет другие раздачи.

## Проверки

Локальное ядро: 1920 total /1918 PASS /0 FAIL /2 ожидаемых optional private-source skips. Новый browser regression проверяет реальное OPEN_BOOSTER, полное равенство сохранённого результата reducer, normal/reduced motion, отсутствие повторного удаления карт и layout-полётов, одновременность раздачи/раскрытия и разблокировку руки.

Независимое ревью: подтверждённых Critical/Important нет. Четыре реальных browser-сценария PASS: Mega→цель→Strength→остаток→skip (normal/reduced), Charm tag и Ethereal tag→целевая рука→skip→Big blind. Промежуточный полёт915px просмотрен.

Последовательная пара исходная0.4.59 / исправление на том же Chromium138 с CPU×4 и timeline/profiler: normal full-field renders3→1, удалённые hand16→0/pack10→0, layout-flights16→0 (включая лишнюю compact-анимацию), раскрытие/раздача sequential→overlap. Wall-time всего тестового drag-to-ready2188→1659ms; это один инструментированный замер с CDP, не телефонный FPS и не гарантия времени на устройстве. Save6.8→6.7ms почти неизменён. Общий timeline Layout count65→65, time37.97→65.02ms — общего снижения Layout time не доказано, другие источники layout/paint остаются. Reduced-motion также сохраняет узлы, без искусственных задержек.

Дополнительные старые standalone `arcana-pack-check.mjs` и `remaining-pack-check.mjs` не входят активную CI-матрицу и остановились на устаревших действиях: owned-strength `.shop-use` после сброса выбора изменением цели, Standard `TAKE_PACK_CARD` через прежнюю `.shop-use`. Первый сбой воспроизведён также с исходными0.4.59 модулями через source routing. Временная правка старого Arcana затем встретила его прежнее ожидание полного stage внутри viewport; она отменена. Тестовый долг Т-01 зарегистрирован. Рабочие новые/активные проверки используют действующие зоны; старые тесты не объявлены прошедшими.

Локальные активные целевые suites PASS: card-action-motion, card-motion, score-flow, pack-selection-performance, pack-take-performance, pack-opening-performance (включая отказ сохранения→без раскрытия→повтор после восстановления хранилища). Android offline assets и check-config PASS; native compilation/CI/APK PASS (см. итог ниже).

## Ограничения

Физический Android/WebView/FPS/диск недоступны. Нельзя утверждать, что устранён каждый фриз на телефоне. Native CardStorage всё ещё синхронный: чтение current, запись backup и current до успешной анимации. Замер памяти Node median7: история2/202/802/2002 действий → dispatch1.25/1.50/3.26/6.27ms, save5.99/7.13/15.43/27.00ms; при2002 через native bridge проходит1.302MB. Эти числа не измеряют Android I/O. Асинхронное сохранение без подтверждённого device bottleneck в эту правку не включено; CAS и durability сохранены.

# Независимая проверка руки и добора — 0.3.7

Проверена последовательность: сохранение результата одного действия → временная рука только из прежних оставшихся карт → закрытие промежутков → разыгрывание/подсчёт либо сброс → окончательная отсортированная рука и полёт новых карт из колоды. UI-анимация не выполняет дополнительных действий ядра.

## Результаты

- tests/ui/hand-gap-check.mjs: игра и сброс на 1536×688 и 915×412, четыре сценария прошли. При остановленной исходящей анимации в DOM находятся ровно оставшиеся прежние карты; шаг между карточными слотами 82 логических пикселя, скрытых слотов для добора нет. После завершения DOM равен сохранённой руке, revision увеличен только на один; played-card/dealing отсутствуют.
- tests/ui/score-flow-check.mjs: итоговый прогон на 1536×688 и 915×412 прошёл. Сортировка переживает перезагрузку, сброс и добор работают; порядок всплывающих очков совпадает с trace. Существующие проверки цвета/умножения/пламени/колоды не регрессировали.
- tests/ui/deck-reference-check.mjs: окончательный прогон всех шести размеров прошёл; включая названия/описания красной и синей колоды и их отражение в деталях партии.

Независимый дополнительный Chromium-сценарий сравнил всё десериализованное состояние UI с прямым результатом dispatch (включая RNG, revision, счётчики, руку и зоны карт). Проверены шесть случаев: rank, suit, пустая стопка добора, победа блайнда, reduced-motion с rank и с suit. Все прошли. Исходная рука намеренно имела ручной порядок; после добора итог совпал с выбранной сортировкой ядра. При пустом доборе остаются шесть карт без остаточных клонированных элементов; после победы также шесть карт и нет лишнего добора. Reduced motion корректно завершается без зависания.

## Замечание к старой проверке

Первый прогон score-flow завершился ошибкой старого ожидания «новые карты скрыты .dealing во время сброса». Это противоречило новому требованию отсутствия невидимых слотов. Исполнитель заменил проверку точным набором оставшихся прежних ID и отсутствием новых карт до добора; повторный независимый прогон прошёл.

## Проверка кода

prepareHandMovement сохраняет позиции только существующих ID и применяет переходы к пережившим рендер картам. Временный render использует копию состояния с сокращённым массивом hand, не изменяя уже сохранённое игровое состояние. Ветвь добора выполняется только при непустом событии cards_drawn. При выигрыше и пустой стопке она пропускается. Выбранный режим сортировки остаётся ответственностью ядра; анимация не вызывает дополнительных SET_SORT, draw или изменения RNG.

Открытых замечаний нет. Проверка браузерная; физическое Android-устройство не использовалось.

# Начальный экран «Пьеро»: промежуточный UI

## Источники и границы

Просмотрены полностью открытое главное меню `05-Screenshot_2026-09-08-10-54-09-13...jpg` и загруженные скриншоты `02-Screenshot_2026-09-08-11-00-40-32...jpg` (магазин) и `03-Screenshot_2026-09-08-10-53-58-58...jpg` (выбор языка поверх главного меню). Из оригинального APK прочитаны `assets/functions/UI_definitions.lua`: `create_UIBox_main_menu_buttons` (6072–6125), `G.UIDEF.run_setup_option` (5837–6000). Lua и оригинальные картинки не входят в созданные ресурсы.

Оригинал располагает большую кнопку игры в нижней горизонтальной панели, настройки рядом, выбор новой/продолжаемой партии — во вкладках подготовки. Собственная надпись «Пьеро», фон печатной мастерской, Rubik и собственная существующая рубашка сохранены. Основная нижняя панель, профиль слева и язык справа размещены по пропорциям скриншота 2048×917, приведённым к 1536×688. Пиксельное равенство не заявлено при собственных фоне, логотипе и шрифте.

В основной панели Играть/Настройки/Коллекция. Коллекция пока disabled с явной доступной подписью ограничения. Профиль P1 — read-only, Русский — disabled статус. Продолжение сохранённой партии находится только во вкладке подготовки. Сложности и испытания пока отсутствуют. В подготовке доступны Красная/Синяя колоды из существующего `DECKS` и необязательное зерно (до 8 символов, uppercase — по `button_callbacks.lua:1951`). Совпадение последовательности RNG с оригиналом по тому же зерну пока не заявляется. Информационная геометрия и всё оформление остаются в единой координатной системе существующего поля **1536×688**; это фактический размер `#stage`, а не 1536×708.

## Контракт интеграции

Подключить `/web/start-screen.css` один раз. Импортировать `renderStartScreen`, `removeStartScreen` из `src/ui/start-screen.js`.

```js
renderStartScreen({
  hasSave: Boolean(savedState),
  onContinue: () => { removeStartScreen(); restoreRun(savedState); },
  onNew: ({deckId, seed}) => {
    // Создать новое состояние в blind_selection; не начинать блайнд автоматически.
    removeStartScreen();
    startNewRun({deckId, seed});
  },
  onSettings: openSettings,
});
```

Это пример контракта, `restoreRun/startNewRun/openSettings` предоставляет интегратор. Модуль не создаёт ядро, не читает/стирает сохранение. `seed` — строка после trim/uppercase, максимум 8 символов, либо undefined. Повторный render удаляет старое меню, remove восстанавливает прежний фокус. Меню и подготовка выезжают снизу за 360 мс; при reduced-motion анимации отсутствуют.

Основные селекторы: `#start_screen`, `#start_new`, `#start_collection`, `#setup_continue_tab`, `#start_settings`, `#setup_deck_red`, `#setup_deck_blue`, `#setup_seed`, `#setup_play`, `#setup_back`.

## Выполненная проверка

- `node --check src/ui/start-screen.js` — успешно.
- Минимальная проверка DOM в Node — успешно: продолжение отключено без сохранения; клик новой игры только открывает подготовку и не вызывает onNew; выбор синей колоды/длинного зерна возвращает `{deckId:'blue',seed:'DEMO1234'}`; продолжение вызывает callback; remove удаляет экран.
- Настоящие браузерные и Android-проверки интегрированной начальной сцены ещё требуются. Минимальная проверка DOM не доказывает визуальную геометрию, клавиатуру Android или реальные переходы ядра.

После сверки полностью открытого референса обновлено: продолжение перенесено только в подготовку; основной ряд копирует состав Играть/Настройки/Коллекция, показаны read-only профиль и язык. Обновлённая минимальная DOM-проверка выполнена: #start_continue отсутствует, Коллекция disabled, #setup_continue_tab gated по hasSave, callback получает uppercase зерно максимум8символов; интеграционная браузерная проверка остаётся обязательной.

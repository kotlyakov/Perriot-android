# Реальный запуск исходного Lua-рендерера: геометрия оригинала

25.10.2026. Исследование приложенного `01-Balatro_1.0.1n_0.4_25_noPairip.apk`, SHA-256 `6236dc68a312d04295839cfbfd2699d4751877bdf162c3a4ce425481d28397bd`. Это **не запуск APK на Android**. В контейнере реально запущен извлечённый оригинальный Lua-код и его графический рендерер на desktop LÖVE11.5, Xvfb и программном OpenGL. Оригинальные ресурсы используются только для локальной исследовательской проверки; в release/source/assets Пьеро они не включались.

## Условия и воспроизводимость

В среде не было love, Xvfb, adb, emulator или /dev/kvm. Через штатный apt repository скачаны .deb LÖVE11.5/Xvfb/xdotool и зависимости; распакованы в `/tmp/pierrot-runtime` без установки пакетов. Для XKB временно скопирован исполняемый xkbcomp в /usr/bin. Xvfb работает через TCP внутри одного процесса проверки: unix sockets среды недоступны. Проверочный скрипт `/tmp/pierrot-native-reference/run-size.py`, исходники только в `/tmp/pierrot-native-reference/assets`. Кадры и дампы размеров сохранены в игнорируемой `artifacts/native-reference/`, отдельно русские в `artifacts/native-reference/ru/<viewport>/`.

Desktop runtime не имеет custom `love.platform`, поэтому добавлен минимальный локальный модуль: offline load/save через love.filesystem, пустые callback pumps, isPremium=true, isArcade=false, isOffline=false. В main до создания G подставлен getOS()=Android, поэтому оригинальные F_MOBILE, мобильные высоты кнопок, отключение sound thread и другие ветки Android реально включены. Системная интеграция/облачные сохранения не воспроизведены. Для автоматизации пропущен splash (Game.splash_screen вызывает оригинальный main_menu), через штатные callbacks открыты New Run, Party, Collection, Profile и начата партия seed13031990/White Stake. Инструментирование update вызывает callbacks, captureScreenshot и записывает T-координаты; исходные функции компоновки/метрики шрифта/рисования не менялись. Русская локализация выбирается в startup настройкой language=ru. Desktop antialiasing/driver/touch/insets отличаются от Android; не объявляем кадры физической приёмкой.

Первая попытка без shim завершилась ожидаемой ошибкой main.lua155 (love.platform=nil); первая попытка прямого start_run во время splash имела конфликт жизненного цикла. Эти кадры не используются как поле. Чистый повтор использует оригинальный G.FUNCS.start_run, затем select_blind с исходным UIElement. Итоговое field.png показывает Small Blind, 8/8, 44/52, а не смешанный экран меню.

## Точный алгоритм из приложенного APK

main.lua435–486, game.lua1072–1089, globals.lua298–301: TILE_W=21, TILE_H=11.2, paddingW=.8, paddingH=.4. Область масштабирования 22.6×12.4. Размер пикселя игровой единицы `u=min(viewportW/22.6,viewportH/12.4)`. Для aspect<22.6/12.4: roomX=.8, roomY=(viewportH/u-11.2)/2. Иначе roomY=.4, roomX=(viewportW/u-21)/2. Это установленный алгоритм данного APK, а не догадка по старому JPEG.

| Viewport | u (px/unit) | ROOM x px | ROOM y px | ROOM w px | ROOM h px |
|---|---:|---:|---:|---:|---:|
|1536×688|55.483871|185.419355|22.193548|1165.161290|621.419355|
|915×412|33.225806|108.629032|13.290323|697.741935|372.129032|
|1536×864|67.964602|54.371681|51.398230|1427.256637|761.203540|

Таблица — расчёт исходных координат до динамического room jiggle/CRT, не bounding box скриншота. В узкой ветке roomY центрирует ROOM, в широкой фиксирован .4. Поэтому простое центрирование масштабированной базы1536×688 недодаёт .2u по Y при16:9 (13.592920px для1536×864). По X равномерный масштаб с центрированием подходит. Порог имеет ветвление .4 против .6 игровых единиц по Y, его нельзя незаметно заменить линейной интерполяцией под видом точного оригинала.

HUD имеет собственную ширину5.25unit (291.290323px широкий,356.814159px16:9), anchor cli с offsetX=-.7 относительно ROOM_ATTACH. Его T.h30.16 относится к уходящему за экран фону и не является высотой видимого окна. Положение может колебаться из-за room jiggle. Прежняя оценка width382px из JPEG1536×864 не соответствует этому APK автоматически: референс имел другую заявленную версию/состояние.

## Что теперь можно и чего пока нельзя закрывать

Блокер «оригинальный рендерер вообще не запущен» снят для локального desktop Lua-рендерера. У-20/21/22 теперь можно исправлять по фактическому алгоритму этого APK, отдельным размерам UIBox и парным кадрам, сохраняя утверждённые собственные стили/главные кнопки/меню. Дампы содержат реальные логические размеры, кадры — реальное рисование исходного Lua. Внешняя светлая рамка после CRT может отличаться от логического T на несколько пикселей.

Г-06 как физическая Android-приёмка остаётся отдельно: нет Android emulator/device, фактических system insets и Android graphics. Нельзя объявить новый APK Пьеро визуально принятым пользователем только по desktop паре. Ранее пропавшие JPEG также не восстановлены этим запуском. Доступна автономная сверка конкретных состояний и aspect по приложенному APK; не нужно снова просить пользователя присылать уже имеющийся APK.
